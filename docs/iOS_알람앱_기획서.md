# 알람천국 iOS 기획서 — 기본 기능 및 일정·메모 확장

최종 수정: 2026-11-13 (최초 2026-11-09)<br>
표시명: 알람천국 / iOS: AlarmApp-iOS / Android: AlarmApp-Android

## 검토 요약

- Phase 1: iPhone / Swift+SwiftUI **네이티브만**
- 크로스플랫폼(Flutter, RN, KMP 등) **제외**
- Android는 별도 저장소의 네이티브 앱으로 관리한다. 일정·예외·메모의 제품 규칙은 양 플랫폼에 동일하게 적용하고, OS 알람 예약은 플랫폼별로 구현한다(코드 공유 목표 아님).
- 0~10절은 기본 기능 범위이며, 일정·메모 확장에는 **11절의 규칙을 우선 적용**한다. 확장 구현 시 기존 데이터와 알람 동작을 보존한다.

## 0. 결정 사항

- 기기: iPhone만
- 최소 OS: iOS 26.0 이상 (AlarmKit). 이후 OS는 기본 호환. iOS 25 이하 비대상
- 참고 이미지 `알람실행화면.png`: 앱 실행 후 알람 화면 레퍼런스 (잠금화면 아님)
- 앱 표시 이름(양 플랫폼): **알람천국**
- iOS 프로젝트: **AlarmApp-iOS** (타깃명 `AlarmApp` 가능)
- Android 프로젝트: **AlarmApp-Android** (별도 저장소)
- 번들 ID / applicationId: `com.alarmheaven.alarm` (확정)
- 브랜드 톤: 밝고 힘찬 (밝은 배경 + 강한 CTA)
- 테마: **Phase 1 라이트 고정**. Phase 2(기능 업데이트)에서 톤다운 다크 + 라이트/다크/시스템 따름 추가

## 1. 제품 정의

강제 기상 유틸리티. 미션 완료 전까지 앱 안에서 알람을 끌 수 없다.  
참고: 알라미. 개인용 MVP (1:1 복제 아님).

## 3. 핵심 흐름

1. 알람 on → 시각에 AlarmKit 시스템 울림  
2. 시스템 주 액션으로 앱 열기  
3. 앱 알람 실행 화면 → 미션 시작 → 미션 완료 → 알람 정지  

규칙:
- 시스템 주 버튼 = 앱으로 보내기 (미션 없는 즉시 종료를 기본으로 두지 않음). 시스템 알림의 보조 버튼 문구: "미션하러 가기"
- OS가 Stop을 강제 노출하면 한계는 리스크로 수용
- 실행 화면은 **미션 완료로만** 닫힌다 (뒤로가기·스와이프 불가)
- 미션 완료 시 지금 울리는 알람만 정지하고, 반복 예약은 유지한다
- 앱을 열었을 때 시스템 알람 소리가 멈춰 있으면, 미션이 끝날 때까지 앱이 알람 소리를 직접 반복 재생한다(무음 모드에서도)
- 알람을 찾을 수 없거나 문구 파일이 없어도 **미션 없이 꺼지지 않는다** (기본 미디어·소리 + 흔들기로 대체)
- 미리보기는 **편집 화면에서만**, `미리보기 종료` 표시. 미리보기에서도 미션을 해 볼 수 있지만 알람을 정지하지 않는다

## 4. 기능 (MVP)

### 설정
- 메인 우측 상단 톱니바퀴 → 설정 화면
- 언어: 설정 화면의 "언어 ›" 한 줄 → 언어 선택 화면(시스템 설정 / 한국어 / English). 고르면 즉시 적용. 시스템 언어가 한·영이 아니면 한국어
- 권한 안내: 알람 권한이 **꺼져 있거나 아직 묻지 않았을 때만** 표시. `설정 열기`는 미결정이면 앱 안 권한 창, 허용·거부 상태면 iPhone 설정의 알람천국 항목으로 이동
- 테마: Phase 1에서는 없음(라이트 고정). 2차에서 라이트/다크/시스템 추가

### 알람
- 최대 10개 (초과 시 추가 차단)
- 요일 1개 이상 필수 + 오전/오후 시간
- 타이틀 필수
- on/off, 삭제(로컬+AlarmKit). 삭제는 리스트에서 왼쪽으로 밀기 · 카드 길게 누르기 · 편집 화면 휴지통(확인창)
- 알람 권한이 꺼져 있으면 메인 상단에 경고 배너(설정 경로 안내 + `설정 열기`)
- 리스트: 시간·요일·타이틀·on/off·다음 울림까지 N시간 M분 (해당 없으면 숨김)
- 생성 기본값: 미션=흔들기, 미디어=`와장창 댕댕이` 영상, 소리=`아침이 왔다잖아` (카탈로그 `default: true`), 시각 07:00, 요일 월~금, 타이틀 빈칸(입력 필수), 따라쓰기 문장 = 전체
- 남은 시간은 분 단위 올림(1분 30초 → 2분)
- 빈 목록: 빈 상태 + 추가 CTA

### 미션 (알람당 1개 필수)
1. **흔들기 10회** — 가속도 기준(4.0g, 실기기에서 조정 예정). 진행 링과 n/10 표시, 7회부터 "거의 다 왔어요!"
2. **따라쓰기** — 앞뒤 공백만 무시하고 **완전 일치**(대소문자 구분). 입력이 일치하는 순간 완료
   - 문장은 카테고리 4개(자기 확언 / 사랑 / 학업 / 동기부여) × 3문장 = 12문장, 각 문장에 한국어·영어가 있다
   - **알람마다 출제할 문장을 고른다**: 편집 화면에서 따라쓰기를 고르면 "미션 문장 ›" → 미션 문장 고르기 화면(카테고리 탭 · 탭별 전체 선택 · 문장별 체크, 0개면 확인 불가). 알람이 울리면 고른 문장 중 무작위 하나
   - 앱 언어의 문장으로 출제·판정한다. 문장 선택은 언어를 바꿔도 유지된다
   - 문장 작성 기준: 짧게, 띄어쓰기가 헷갈리지 않게, 문장부호·숫자·이모지 없이. 영어는 첫 글자만 대문자, 중간 대문자와 아포스트로피 금지

### 실행 화면
- **전체 화면 배경 동영상**(음소거·반복 재생) 위에 날짜·큰 시각(24시간제 `HH:mm`)·타이틀·미션 시작
- 날짜·시각은 상단 1/3, 미션 시작은 하단. 영상은 이 영역을 비워 두고 만든다
- 실행 → 미션 → 완료("미션 완료! 좋은 아침이에요", 진동) → 닫힘. 울리는 동안 화면이 꺼지지 않는다

### 미디어·소리
- 미디어: 동영상 3개 번들 (모두 1080×1920 · 7초 루프 · 무음, 기본값은 강아지)
  - `media_puppy_crack.mp4` `와장창 댕댕이` — 강아지가 폰 화면을 마구 두드려 깨뜨리는 2D 일러스트
  - `media_cat_push.mp4` `책상 위 냥이` — 고양이가 앞발로 폰을 책상 끝까지 밀어내 아슬아슬하게 만드는 2D 일러스트
  - `media_shaking_clock.mp4` `들썩들썩 알람` — 알람 시계가 종을 울리며 좌우로 크게 흔들리는 2D 일러스트(민트 배경)
- 소리: 2개 번들 (mp3). 소리·미디어 표시명은 앱 언어를 따른다(한/영). AlarmKit 알람 소리는 같은 소리의 `.caf` 변환본, 앱 안 재생은 mp3
- 알람별 선택. 영상 소리는 쓰지 않고 알람 소리는 카탈로그 소리로 재생

## 5. 화면

메인 / 편집·생성 / 미션 문장 고르기 / 설정 / 언어 선택 / 알람 실행 / 미션 / 미리보기

## 6. 데이터

- Alarm, MissionType(shake|transcription), MediaAsset, SoundAsset, AppSettings, TranscriptionPrompt  
- Alarm: 시각·요일·타이틀·켜짐·미션·미디어·소리·**따라쓰기 문장 선택**(빈 값 = 전체)
- SwiftData가 원본, AlarmKit은 파생. 저장 후 예약하고, 예약이 실패해도 데이터는 남기고 앱 시작·활성화 때 다시 맞춘다
- 미디어·소리·문장은 번들 파일(카탈로그·문구 JSON)이 원본이고 SwiftData에 저장하지 않는다

## 7. 권한

- **알람(AlarmKit)만 필수.** 설명문: "설정한 시각에 미션 알람을 울리기 위해 사용합니다."
- 권한 요청은 사용자 동작(알람 저장·켜기·`설정 열기`)에서만 한다. 앱이 활성화되기 전에 요청하면 시스템이 창 없이 거부하기 때문
- Core Motion(흔들기)은 가속도만 읽어 권한이 필요 없다. 알림·마이크·카메라·위치 권한 없음
- Widget Extension은 지금 없음(카운트다운 표시가 필요해지면 검토)
- 알람 권한 스위치로 바로 가는 공개 링크는 없다. 앱 설정 항목까지만 보낼 수 있다

## 8. 비범위

Phase 1: Android, iPad, iOS 25↓, 크로스플랫폼, 클라우드, 단발 알람, 스누즈/통계/유료, 잠금화면 장악, **다크 테마**  
별도 확장: 톤다운 다크 + 테마 설정(라이트/다크/시스템). Android는 별도 저장소에서 관리한다.

이번 일정·메모 확장의 제외 범위: 조용한 기상 모드, 음량 단계 전환, Watch·이어폰 우선 기상, 계정·로그인, 서버 백업·복원, 클라우드 동기화, 결제. 신규 미션·퀵알람·습관 알람도 이번 확장에 포함하지 않는다.

## 9. 리스크

- 시스템 UI ≠ 앱 실행 UI  
- 시스템 Stop 100% 차단 불가 가능  
- 앱 kill 후 미션 강제 약함  
- 실기기·Mac 필수  
- 실행 화면 영상 재생이 알람 소리(오디오 세션)를 끊지 않아야 함  
- `아침이 왔다잖아`는 33.7초 — 알림 소리 30초 제한에 걸려 기본음이 될 수 있음(실기기 확인)  
- 흔들기 기준값·영어 키보드 자동 대문자·한글 조합 중 판정은 실기기 확인 필요  
- 따라쓰기 완전 일치 규칙상 띄어쓰기 실수로 실패할 수 있음 → 실기기에서 실패가 잦으면 규칙 재검토  

## 10. 디자인 톤 · 화면 와이어

### 브랜드
아침 햇살처럼 밝고, 미션 버튼은 힘차게.

| 토큰 | 안 | 역할 |
|------|-----|------|
| bg | `#FFF8F0` | 기본 배경 |
| brand-sun | `#FFC107` | 햇살 포인트, 토글 on |
| cta | `#FF3B30`~`#FF5A5F` | 미션 시작 등 |
| text | `#1A1A1A` / 실행화면 시각은 화이트+섀도 | |

피함: 다크 기본, 퍼플 네온, 무거운 세리프 신문 톤.

- UI 타이포: 둥근 산세리프 볼드 (SF Rounded 계열)
- 실행 화면 미디어는 전체 화면 배경 동영상(브랜드 타이포와 분리). 시각은 화이트+섀도로 영상 위 가독성 확보
- 미디어 연출: 깜빡임(화면 전체 번쩍임) 금지, 흔들림·금 효과로 표현
- 모션: CTA 스프링, 토글 점등, 미션 완료 짧은 피드백

### 화면 구조
- **메인:** 알람천국 워드마크 · 설정(톱니바퀴) · 권한 경고 배너(꺼져 있을 때) · 리스트(시간/요일/타이틀/남은 시간/on·off, 밀어서·길게 눌러 삭제) · 추가(10개면 비활성 + 안내) · 빈 상태
- **편집:** 시간·요일·타이틀·미션(+따라쓰기면 미션 문장)·미디어·소리 · 미리보기 · 저장 · 삭제(휴지통)
- **미션 문장 고르기:** 취소 / 확인 · 카테고리 탭(고른 개수 배지) · 전체 선택 · 문장 체크
- **설정:** 일반(언어 ›) · 권한 안내(필요할 때만)
- **실행:** 전체 화면 배경 영상 + 레퍼런스 레이아웃(날짜·시각·뱃지·미션 시작). 뒤로가기로 끄기 없음
- **미리보기:** 실행 + 미리보기 종료
- **미션:** 흔들기 n/10 또는 따라쓰기 입력 → 완료 피드백 → 정지

카피 톤: 밝고 짧게. 레퍼런스 중앙 장문은 미디어 예시일 뿐 앱 기본 톤 아님.

## 11. 생활·근무 일정 및 메모 읽어주기

### 11.1 목적과 범위

날짜에 맞춰 울리고, 오늘 일어나야 하는 이유를 알려주는 알람으로 확장한다. 일반 사용자의 평일·주말 차이부터 특정 날짜 변경, 2교대·3교대 등 순환 근무와 불규칙 근무표까지 하나의 일정 체계로 다룬다.

- 기존 흔들기·따라쓰기, 영상·소리, 미션 완료 후 알람 정지 규칙은 유지한다.
- 저장은 기기 로컬을 기준으로 하며 계정·백엔드는 이번 범위에 넣지 않는다.
- 사용자에게 보이는 모든 화면·안내·접근성 문구는 한국어·영어를 함께 제공한다.
- 자동 공휴일 조회·외부 캘린더 연동은 포함하지 않는다. 휴일은 사용자가 날짜 예외로 지정한다.

### 11.2 화면 구성과 사용자 흐름

메인은 가장 가까운 실제 기상 예정 시각을 상단에 표시하고, 아래에 일정 목록·달력 보기 전환을 제공한다. 권한 경고와 설정 진입은 유지한다.

- 다음 기상: 날짜, 시각, 일정 이름, 적용 이유, 미션 요약, 메모 요약.
- 적용 이유: 기본 요일 일정 / 순환 근무 / 직접 지정 / 특정 날짜 변경 등을 구분.
- 달력: 날짜별 실제 울릴 시각과 근무 유형 표시. 건너뛴 날짜와 변경된 날짜도 구분.
- 날짜 상세: 해당 날짜에 적용되는 일정과 알람을 모두 표시하고 수정 대상을 선택.
- 일정 만들기: 일정 이름 → 일정 방식 → 시각·근무 규칙 → 미션·영상·소리·메모 → 향후 날짜별 미리보기 → 저장.
- 날짜별 목록은 같은 일정 계산 결과를 사용한다. 표시된 예정 시각과 OS 예약 결과를 별도 로직으로 계산하지 않는다.

표시 예:

> 다음 기상: 내일 오전 9:00 · 주말 일정
>
> 월요일 오전 5:30 · 이번 날짜만 변경
>
> 화요일 오전 7:00 · 평일 일정

### 11.3 일정 방식

하나의 일정은 아래 방식 중 하나를 사용한다. 여러 일정은 독립적으로 켜고 끌 수 있다.

| 방식 | 필수 설정 | 규칙 |
|---|---|---|
| 요일 반복 | 요일 그룹과 각 기상 시각 | 예: 월~금 07:00, 토·일 09:00. 같은 일정 안에서 같은 요일을 중복 지정하지 않는다. 지정하지 않은 요일은 울리지 않는다. |
| 순환 반복 | 기준 시작일, 순서가 있는 근무 유형 목록 | 요일과 무관하게 순서를 반복한다. 시작일을 순환 첫날로 계산하며 예외 변경 때문에 이후 순환 순서가 밀리지 않는다. |
| 달력 직접 지정 | 날짜별 근무 유형 | 등록한 날짜에만 적용한다. 미지정 날짜를 자동으로 휴무나 다른 근무로 추정하지 않는다. |

순환 예: 주간 → 주간 → 야간 → 야간 → 휴무 → 휴무. 이는 예시이며, ‘2교대’·‘3교대’라는 명칭만으로 근무 순서나 시각을 강제하지 않는다.

근무 유형에는 사용자 지정 이름과 기상 시각 또는 ‘알람 없음’을 설정한다. 휴무도 09:00 알람처럼 시각을 지정할 수 있다. 초기 설정은 적용 날짜가 실제 **알람이 울릴 날짜**임을 명시하고, 야간 근무일과 기상일이 혼동되지 않도록 한다. 근무 시작 시각에서 기상 시각을 자동 역산하는 기능은 포함하지 않는다.

### 11.4 날짜별 예외

달력에서 날짜를 선택하면 ‘이 날짜만 변경’을 기본 동작으로 제공한다.

| 동작 | 결과 |
|---|---|
| 시각 변경 | 해당 일정의 그날 시각을 교체. 원래 시각에 중복으로 울리지 않음 |
| 근무 변경 | 순환·직접 지정 일정의 해당 날짜 근무 유형을 교체 |
| 건너뛰기 | 해당 일정의 그날 회차만 제외 |
| 메모 변경 | 그날 읽을 메모만 변경 |
| 변경 취소 | 해당 날짜의 예외를 제거하고 기본 규칙으로 복귀 |

- 예외는 ‘대상 일정 + 알람 날짜’로 식별한다. 한 날짜의 수정으로 다른 독립 일정까지 변경하지 않는다.
- 기본 일정 계산 → 날짜 예외 적용 → 최종 울림 시각·설정 결정 → OS 예약 순서로 처리한다.
- 시각 변경은 추가 알람 생성이 아니다. 같은 회차는 한 번만 울린다.
- 예외가 끝나면 다음 날짜부터 기본 규칙을 적용한다. 예외 적용이 기본 시각이나 순환 기준일을 바꾸지 않는다.
- 건너뛰기는 해당 날짜의 소리와 메모 읽기 모두 실행하지 않는다.
- 앞으로 계속 적용할 변경은 별도 일정 편집에서 수행한다. 적용 시작 날짜를 지정하며 기존 날짜 예외는 유지하고 충돌·영향을 미리보기로 보여준다.
- 이미 울리는 알람은 일정 재계산 때문에 취소하지 않는다. 울리는 회차는 기존 미션 완료 흐름으로 처리한다.

예: 월~금 07:00 일정에서 월요일만 05:30으로 변경하면 월요일 05:30에만 울리고, 화요일은 07:00으로 복귀한다.

### 11.5 미션·영상·소리 설정

- 일정별 기본 미션·영상·소리를 설정한다. 미션은 기존과 같이 한 회차당 정확히 하나다.
- 근무 유형별로 기본값 사용 또는 별도 설정을 선택할 수 있다. 고급 설정은 처음에는 접어서 표시한다.
- 최종 설정은 일정 기본값에 근무 유형별 변경을 적용해 결정한다. 날짜 메모 예외는 마지막에 적용한다.
- 기본값을 상속하는지 별도 값인지 저장 단계부터 구분한다. 기본 설정이 바뀌어도 명시적으로 덮어쓴 근무 설정은 유지한다.
- 기존 알람은 동일한 요일·시각·켜짐 상태·미션·미디어·소리·문장 선택을 유지하는 요일 반복 일정으로 옮긴다. 전환으로 예약을 중복 생성하지 않는다.

### 11.6 메모 읽어주기

알람 표시 이름과 읽을 메모는 별도 필드다. 메모는 미션 따라쓰기 문장과도 별개다.

- 일정별 기본 메모, 읽기 켜기·끄기, 저장 전 ‘들어보기’를 제공한다.
- 특정 날짜의 메모는 ‘기본 메모 사용 / 이날만 다른 메모 / 이날은 읽지 않기’를 구분한다. 빈 문자열만으로 상속과 읽기 해제를 동시에 표현하지 않는다.
- 사용자가 작성한 한국어·영어 메모의 음성 언어를 지원하며, 앱 UI 언어와 사용자 메모 언어는 분리한다. 자동 언어 판별이 불명확한 경우 선택할 수 있게 한다. 사용자 메모를 임의 번역하지 않는다.
- 첫 제공 범위는 **실제 알람 실행 화면 진입 후 회차당 한 번 읽기**다. 화면 재렌더링·앱 복귀만으로 반복 재생하지 않는다.
- 메모 재생 중에도 미션을 바로 시작할 수 있다. 미션 시작·알람 완료·실행 화면 종료 시 음성 재생을 중단한다.
- 음성 재생 실패가 미션 수행이나 알람 정지를 막으면 안 된다. 메모 텍스트는 화면에서 확인할 수 있게 한다.
- 음성 때문에 알람 재생 세션을 종료하거나 미션 없이 알람을 끄지 않는다. 말소리를 알아들을 수 있는 믹싱·음성 재생 정책은 실기기 기준으로 정한다.
- ‘들어보기’는 시스템 예약과 알람 상태를 바꾸지 않으며 사용자가 중단할 수 있다.
- 잠금화면·앱 종료 상태에서 최초 울림과 동시에 메모를 읽는 기능은 이번 범위에 넣지 않는다.

예: 이름 ‘이른 출근’, 메모 ‘오늘은 여섯 시 반에 출발해야 해요. 출입증 챙기세요’.

### 11.7 데이터와 예약 경계

아래는 논리적 구성이다. 실제 모델 이름과 테이블 분할은 구현 설계에서 정한다.

| 구성 | 역할 |
|---|---|
| 일정 | 이름, 방식, 활성화 여부, 적용 시작일, 순환 기준일 |
| 일정 규칙·근무 유형 | 요일 그룹별 시각, 순환 순서, 날짜별 근무 배정, 알람 없음 여부 |
| 알람 기본 설정 | 미션·문장 선택·미디어·소리·메모·읽기 여부·음성 언어 |
| 날짜별 예외 | 대상 일정·날짜, 시각·근무 교체, 건너뛰기, 메모 정책 |
| 회차·예약 정보 | 적용 일정과 날짜, 최종 울림 시각, OS 알람 ID, 예약 결과, 회차별 메모 재생 식별 |

- 일정과 설정이 원본이며 OS 예약은 파생 데이터다. 모든 변경은 서비스 계층을 통해 저장·예약 반영한다.
- 기존 ‘Alarm 하나 = 시스템 알람 ID 하나’를 전제하지 않는다. 일정·회차·플랫폼 예약을 안정적인 식별자로 연결해 재계산 시 중복을 방지한다.
- 최대 10개는 사용자 관리 단위인 일정 기준을 원칙으로 하고, 파생 OS 예약 수는 별도로 관리한다. 플랫폼 예약 한도로 적용할 수 없는 구성은 저장 전에 안내한다.
- ‘알람 없음’과 건너뛰기를 표현하기 위해 빈 요일이나 임의 시각을 잘못된 값처럼 사용하지 않고 명시적인 상태로 저장한다.
- OS 예약 실패 시 사용자 설정을 보존하고, 실제 예약되지 않은 회차를 예약 성공으로 표시하지 않는다. 재조정은 울리는 회차를 방해하지 않는다.
- 앱 재실행뿐 아니라 장기간 앱 미실행, 기기 재부팅, 시간대·날짜 변경을 고려한다. 매일 앱을 열어야만 순환 예약이 이어지는 설계는 허용하지 않는다.
- 미래 일부 회차를 미리 예약하는 방식은 예약 한도·보충 동작·미실행 지속성을 검증한 범위 안에서만 제공한다. 보장할 수 없는 날짜까지 예약된 것처럼 표시하지 않는다.
- iOS·Android는 같은 입력에 같은 날짜별 결과를 산출하되 OS 권한·예약·재부팅 처리 방식은 플랫폼별로 구현한다.

### 11.8 수용 기준

1. 평일 07:00·주말 09:00 일정이 달력·다음 기상·실제 예약에서 일치한다.
2. 특정 날짜 시각을 교체하면 원래 시각은 울리지 않고 다음 날짜는 기본 규칙으로 복귀한다.
3. 건너뛰기와 변경 취소가 해당 일정의 해당 회차에만 적용된다.
4. 순환 일정은 월·연도 경계를 넘어 같은 순서를 유지하며, 날짜 예외가 이후 순서를 밀지 않는다.
5. 직접 지정 일정의 미지정 날짜에 임의의 알람을 생성하지 않는다.
6. 기본 일정 변경 시 날짜 예외의 적용 결과와 적용 시작일을 미리 확인할 수 있다.
7. 메모 기본값·날짜별 변경·이날 읽지 않기가 구분되며, 회차당 재생 중복과 음성 실패로 인한 알람 해제가 없다.
8. 한국어·영어 UI와 메모 재생, 기존 알람 데이터 전환, 장기간 앱 미실행·재부팅에 대한 동작을 확인한다.

### 11.9 상세 설계 결정 항목

- 시간대 이동 및 일광 절약 시간의 존재하지 않거나 중복되는 시각 처리 규칙.
- 같은 시각에 여러 독립 일정이 겹칠 때 실행 화면·미션·소리 처리 정책.
- 일정 삭제 시 연결된 날짜 예외와 미래 예약의 삭제 범위 및 확인 UI.
- 날짜 직접 지정의 편집 범위, 메모 길이·읽기 속도·음성 기본값, 플랫폼별 예약 가능 범위.

위 항목은 상세 설계에서 확정하며, 자동 처리 방식을 추정해 구현하지 않는다. 개발 진행 상태는 이 문서가 아니라 `CLAUDE.md`에서 관리한다.
